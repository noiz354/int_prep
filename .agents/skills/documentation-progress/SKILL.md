# Documentation and progress

1. Update `progess.md` when a milestone, dependency, test status, risk, or PRD feature status changes.
2. Update `docs/API.md` for endpoint, auth, payload, event, or realtime contract changes.
3. Update `docs/ARCHITECTURE.md` for new service/provider boundaries and deployment implications.
4. Update `docs/IMPLEMENTATION-STATUS.md` and the in-app Feature Catalog label for material PRD progress.
5. State what is real, local mock, adapter, and not yet implemented. Avoid inflated production claims.
6. Include verification commands and results in handoff documentation.
