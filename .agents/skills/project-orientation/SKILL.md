# Project orientation

Use before an unfamiliar, cross-cutting, or ambiguous task.

1. Read `progess.md`, `docs/PRD-100-Features.md`, `docs/ARCHITECTURE.md`, and `docs/IMPLEMENTATION-STATUS.md`.
2. State the relevant PRD ID(s), user outcome, affected boundary, and whether the work is demo-only, adapter-ready, or provider-backed.
3. Identify privacy, candidate-impact, tenant, consent, audit, and performance implications.
4. Select the smallest set of relevant skills and write a short implementation/test plan.
5. Reuse existing adapters and design tokens before adding new packages or abstractions.
6. Update status and docs after delivery.
